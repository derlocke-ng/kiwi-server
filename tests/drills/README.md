# Drills

Tests that break real machines on purpose: a power cut, a backup killed or starved, a full
disk, a master gone, a rebuild from nothing. They are not part of `tests/` because they need
the test machines, take minutes to an hour and leave the machines in a state someone chose.
Run them when the code they cover changes, and before a release that touches it.

Every drill takes the fleet file and the hosts it plays with, and refuses a host that is not
listed in `drills.yaml` next to the fleet file:

```yaml
allowed: [sorbet, papaya, lychee]
```

A live network's fleet directory has no such file, so nothing there can be drilled by mistake.
The drills reach machines the way kiwi-server does (the fleet's admin key and known hosts,
the addresses in the fleet file) and run this tree's `bin/kiwi-server`, so they test what is
checked out. `drill.py` holds what they share.

| Drill | What it does | Covers |
|---|---|---|
| `exit-server-stuck.py FLEET MACHINE` | Makes DNS-over-TLS fail inside a commercial VPN exit, as through a bad server, and waits for the container to be started anew (about eight minutes, the exit is down most of them) | vpn-client's health check, `HealthOnFailure` |
| `master-down.py FLEET MASTER NODE [--minutes 5]` | Stops the master's WireGuard server for some minutes; records which of the node's containers restart, whether the node's own Pi-hole still answers (an uncached name, 5 s twice, as a client asks) and how fast the node reaches the master again | the node's independence, gluetun's reconnect. 11 Nov 2026: nothing restarted, back after 14 s; a single 3 s lookup missed 3 of 10 (strict-order asks the master first), a client's retry is answered |
| `multihop.py FLEET MASTER [--exit-mesh IP]` | A client of a master whose VPN client leaves through another network's master: its public address is the other master's, the first master's names resolve to its own mesh address, the other mesh stays closed (enrolls `drill-multihop` once) | `vpn_provider: custom` on a master |
| `federation.py A B --shared S [--unshared U] [--closed N]` | A client of network B reaches the service A shares (it answers), gets 403 on another name of the same node and nothing from a node not shared; A's names resolve through B's DNS (enrolls `drill-federation` on B once; B's master in B's `drills.yaml`) | `federate`, the link, its firewall and the nodes' nginx rules |
| `soak.py FLEET [--hours 3] [--every 600]` | Watches `status` for hours, read-only: problems as they start and end, containers that restarted, reboots, backups (needs no `drills.yaml`) | a night as the machines live it |
| `backup-server-hung.py FLEET CLIENT SERVER` | Pauses the server's restic REST container and runs a backup on the client: it must end with an error within the module's limits, leave nothing paused, keep the stack up; with the server back the next run must succeed | the backup module's `ASK_LIMIT`, thaw on failure. 11 Nov 2026 (lychee → papaya): gave up after 420 s, nothing paused, next run 3 s |
| `ram-master-power.py FLEET MASTER` | Powers a `coreos-ram` master off and on through netcup's API, runs `watch --once` until it has its role again, checks the WireGuard key and the stack | `targets/ram.py`, `watch` after a hoster's power cycle. 11 Nov 2026 (crumble): role back 134 s after power on, same key; federation drill passed right after |
| `users.py FLEET MASTER [--users 3] [--minutes 20] [--every 60] [--backup-at MIN HOST] [--restart-at MIN UNIT] [--partner FLEET --partner-ssh T] [--client wg\|gluetun]` | Synthetic users: WireGuard clients of the master run here (default: plain kernel WireGuard, wg-quick with the meshes only, as a phone; or gluetun as a node), each round DNS through the Pi-hole, every service's page, 1 MB to Nextcloud over WebDAV and back; per name the checks, failures (and when) and p50/p95. A partner user opens what is shared with it | what people see during a backup, an update, a restart. 11 Nov 2026: 1625 checks in 25 min with a papaya backup, none failed; sorbet's WireGuard server restarted under 3 phone-like users: 9 of 1323 checks failed, all in the round of the restart, papaya and lychee none (keepalive 10 s); gluetun clients take up to 2 min themselves |
| `arm64-vm.sh FLEET HOST [WORKDIR]` | An arm64 board in QEMU (the Debian 13 arm64 cloud image, a `board` login with sudo), taken in by `adopt` and given its role; the VM keeps running for more tests (needs HOST in `drills.yaml`, enrolled, `debian.arch: arm64`) | `adopt`, arm64 nodes |
| `ram-master-vm.sh [WORKDIR]` | Builds a `coreos-ram` master in a throwaway fleet, boots it in a local QEMU VM without a disk, lets `watch` send the role, reboots, lets it send it again; checks the master comes back with the same keys and a fresh `/etc` (a few minutes; touches no fleet machine, so it needs no `drills.yaml`) | `targets/ram.py`, `watch`, `apply` on a blank master |
| `first-run-vm.sh FLEET HOST VM-HOST [RING-HOST:UNIT ...]` | A machine from nothing on a libvirt VM: media, an empty disk, the install, `kiwi-server next`; then restarts with its unlock rings up, one off, all off (the VM's disk is WIPED) | the first run, `disk: auto`, unlock at boot. 13 Nov 2026: quince (uCore, encrypted) and medlar (Debian) pass |
| `starter-vm.sh [WORKDIR] build\|install\|again\|two-disks\|small\|windows\|typed\|all` | The starter image in a local QEMU VM (UEFI, user-mode network): it installs on the one blank disk beside the stick and a USB disk, the first-run page answers on 8740 and 80, the console shows address, code and QR code, kiwi.local answers; started again with the stick first it does not reinstall; two disks or an 8 GB disk install nothing; a disk with Windows on it is erased only after the page's button or ERASE typed at the console (built with `--debug-shell`, a root shell on the VM's second serial port; touches no fleet machine) | `build --starter`, the live system's disk choice, the installed system |
| `starter-vm.sh [WORKDIR] code`, then `first-node` (with `KIWI_NEVER`, `FN_SERVER`, `FN_ADDRESS`, `FN_TOKEN`) | The VM of `install`, still running: `code` puts this checkout's code into its control part; `first-node` makes a new network on its first-run page with "This machine" as the first one at home, has the machine make the master's install media, installs them on a rented server (netcup; THE SERVER IS WIPED), sets the master up from the page, then sets up this machine: it becomes the node, the starter's things go, the control page moves; a hard reset after, and it is still the node | the starter's phase 2: `setup` on a starter, `adopt.run_coreos`, `kiwi-starter-done` |
| `notify.py FLEET CONTROL VICTIM --unit UNIT --site NAME --listener USER@ADDRESS` | Points the fleet's `notify:` at a listener on a device at home (a push topic and a webhook), stops a service on a machine that stays fine, waits for the message that it does not answer, asks the status page without a login, starts the service and waits for "answers again"; the fleet file is put back as it was | `health.py`, `notify.py`, the control node's look, `/status` |
| `page-preview.py [PORT]` (run in the control image, see its head) | The control page on 127.0.0.1 with a throwaway fleet and made-up machines (five fine, one that wants a look, one that does not answer): to look at the page and click it without a real network | the page's look on a computer and a phone, light and dark |
| `app-preview.sh` | The app with the same made-up network (`madeup.py` answers `list`, `status` and `secrets status`), shown in a browser at 127.0.0.1:8087 by GTK's Broadway: to look at the app and click it without a real network | the app's overview, cards and picture |
| `master-vps.sh NEW-DIR PROVIDER SERVER-ID ADDRESS TOKEN-FILE` | A new network from wizard answers whose master is installed on a rented server by `next --yes`, then status, check and a phone (needs `KIWI_NEVER`, the server ids and addresses it must refuse; the server is ERASED) | `init --answers`, `next`, the provider install. 13 Nov 2026: passes on a spare server |
| `regenerate-vm.sh FLEET HOST VM-HOST MODULE FILE` | Writes a marker into a module's data, backs up, changes it, restores the snapshot; then wipes the VM, installs it anew and looks whether the data came back by itself | backup, snapshots, a machine lost and rebuilt. 13 Nov 2026 (quince): all pass |
| `uplink-change.sh FLEET GATEWAY CLIENT-ADDRESS MASTER-SSH [PORT]` | A client behind the gateway while the home's connection is gone for 90 s, and while the tunnel's old path is dead for good (a stale mapping after a new address); nothing on the gateway is restarted | the gateway after the router reconnects. 13 Nov 2026 (quince): nothing leaks, back after 0 s; from a new port by itself after 41 s |
| `logins.py FLEET [MACHINE ...] [--via USER@ADDR]` | Every login `kiwi-server logins` names, tried on the service through its own API, from a device on the network (here, or the one `--via` names); the certificate is checked there too. Sessions it opens are closed; no password is printed or put on a command line | the Logins feature against real services. 14 Nov 2026 from the dev VM: 15 logins on six machines, all in (wg-easy, Pi-hole, Transmission, JDownloader, Portainer, SFTP, Nextcloud, OpenCloud, Paperless) |
| `jabber-doors.py FLEET MACHINE --domain NAME --node USER@ADDR [--public ADDR] [--vpn-via USER@ADDR] [--master USER@ADDR --onion-site SITE]` | Jabber's doors with a throwaway account: logins from the Internet (at the address given, never DNS's), the VPN and Tor (Tor runs on the master only), the page for new accounts with its captcha, a wrong password, and which address the service sees. | A few minutes; the Tor door needs the hidden service to be known. |
| `onion-sites.py FLEET --master USER@ADDR [--master-port N] [SERVICE.MACHINE ...]` | Every hidden service opened through Tor (on the master only): the front page, whether the visitor stays at the .onion address, the page's files, what a browser app is told about its address, and the login form sent the way a visitor's browser sends it (a user that does not exist). With `--logins`: a real login by the service's API where the network has one (Nextcloud, Forgejo, Paperless). The table decides which sites a module marks as usable over Tor. | A minute or two per service; a new one needs a few minutes to be known. |
| `nginx-check.py FLEET MACHINE [MACHINE ...]` | Would the machine's reverse proxy start with what the fleet file says now? Renders into RAM and has nginx read the config (`nginx -t` in a container); nothing is sent. Run it before applying a change to a proxy. | Seconds per machine. |

Each drill prints what it measured, one line per step, and puts back what it changed (a
firewall rule, a stopped container) when it ends, also when it fails half way.
